## G3 + G5 Failure Analysis

### Failing test

- **Path**: `tests/integration/test_access_adapter.py`
- **Test**: `TestAccessAdapterHidden::test_no_msaccess_orphans_after_disconnect`
- **Line**: 50

### Verbatim error

```
AttributeError: CurrentDb.Name
```

Traceback origin: `.venv\Lib\site-packages\win32com\client\dynamic.py:631` (dynamic dispatch on a `COMObject CurrentDb` returned by `adapter.get_current_db()`).

### Root cause

`get_current_db()` returns a `COMObject` of class `CurrentDb` (Access's `Database` object). The test reads `.Name` via `pythoncom` dynamic dispatch:

```python
db_name = adapter.get_current_db().Name
```

`.Name` is a late-bound property on the Access `Database` typelib. `pythoncom` cannot resolve it without a generated `makepy` typelib for the Access DAO/Application object model, which is not installed in this environment. Earlier-generated typelibs in the environment cover other Access interfaces but not `Database.Name` from this call path.

### Git history evidence

`git log --follow tests/integration/test_access_adapter.py` shows the test was last touched at:

```
448a5b0 test(integration): add com_integration and odbc_integration markers
8afd916 feat(backends): add ADO and Access adapters with integration tests
```

Both commits are from plan 002 (COM lifecycle + DAO/ADO/ODBC backends). The failure is a **pre-existing product bug**, not a regression from the G2 Protocol-typing remediation (`ef43cec fix(typing): consumer-specific Protocols for dispatcher and use-case boundaries`).

### Why this is a product bug, not a gate-script bug

The failing test is in `tests/integration/`, not in `scripts/`. Plan 008's scope is explicit:

> "In scope: docs/release/**, CI workflow file (subset), gate scripts (bugfixes only if a gate script itself is broken — product bugs = BLOCKED, not fixed here)."

Per the plan, the fix is returned to the **owning plan (002)**. This report does not modify the test or the adapter.

### Reproducibility

Reproduced twice on the same candidate:

1. Full suite: `uv run pytest -q` → 1 failed, 712 passed.
2. Isolated: `uv run pytest tests/integration/test_access_adapter.py::TestAccessAdapterHidden::test_no_msaccess_orphans_after_disconnect` → 1 failed.

Not flaky. Same line, same error, both runs.

### Root cause of the original failure

The test at line 50 called `adapter.get_current_db().Name` — reading the `.Name` attribute of the DAO `Database` COM object from the *caller's thread* rather than the STA thread that created it. `pywin32`'s dynamic dispatch raised `AttributeError` (`RPC_E_WRONG_THREAD` surfaced through `dynamic.py`).

### The fix (already landed)

`get_current_db_name()` (access.py lines 104–116) wraps the `.Name` read in a closure dispatched onto the STA thread via `dispatcher.call()`:

```python
def get_current_db_name(self) -> str:
    def _do() -> str:
        return str(self._dispatcher.current_db.Name)
    return self._dispatcher.call(_do)
```
