## Known Hazards / Deferred Items

### doctor.py CoInitialize pairs

`doctor.py` calls `CoInitialize` / `CoUninitialize` in a paired pattern for each check. On repeated runs within the same process this is safe; it is documented and intentional — the pattern prevents cross-check pollution. No action required.

### maintenance.py:415 blunt `/IM` kill

`maintenance.py:415` uses `taskkill /F /IM MSACCESS.EXE` (blunt image-name kill) as a last-resort orphan cleanup. This is a separate follow-up from the plan 030 fix (which eliminated `/IM` from the normal teardown path via PID-scoped liveness kill). The blunt kill is retained as an emergency fallback only. Tracking: separate follow-up planned.

### install.ps1:56 uv version pin (cosmetic)

`scripts/install.ps1:56` pins uv `0.12.11` vs the environment's `0.12.13`. G1 is green (the version tolerance in the bootstrap logic handles minor mismatches gracefully). This cosmetic drift does not affect correctness. Left as-is unless G1 fails.

### Root cause of the G6 block

`ComDispatcher._release_com_safe()` called `app.Quit()` from a `ThreadPoolExecutor` worker (no `CoInitialize`, cross-apartment RPC call) → `Quit` failed every round → PID-kill fallback masked the failure → client-process OLE32/RPC state corrupted over 6–9 rounds → `0x800706B5` (RPC_TOO_LATE) or `0xC0000005` (access violation).

### The fix (plan 030 — commit `3ee28b8`)

- `Quit()` dispatched onto the STA thread via `dispatcher.call()` instead of `ThreadPoolExecutor`
- PID-scoped liveness kill added as post-shutdown safety net (by `_access_pid`, never by image name)
- `ThreadPoolExecutor` eliminated from `_release_com_safe`; `gc.collect` added
- `/IM MSACCESS.EXE` never emitted in the normal path
- Reproduction instrument: `C:\Users\METALB~1\AppData\Local\Temp\opencode\diag_com_rounds.py`
